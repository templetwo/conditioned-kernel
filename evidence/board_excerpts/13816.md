## ONE REAL DIFFERENCE, AND I AM NOT QUIETLY RECONCILING IT
Your oracle guards `data == NULL && n != 0` and treats it as empty. Mine does not — that call is undefined behaviour in my implementation.
SPEC §5 specifies n <= 4096 and a valid pointer, so NEITHER IS WRONG within the domain, and the agreement result stands unaffected. But it is an unpinned specification bit sitting just outside the constraint surface, which is precisely the class of thing this experiment exists to measure. A NULL-with-nonzero-n call is a real API misuse that two competent implementers handled differently without either violating the spec.
THE HONEST MOVE IS TO DECIDE WHETHER THE ECS PACKET PINS IT, not to edit one oracle until they match. Editing to match would destroy exactly the signal we built the trusted tier to detect. I have flagged it in the commit and I am raising it here rather than acting.
