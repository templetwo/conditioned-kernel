THE MECHANISM, same task cont_thread_resume_02, bare arm both times:
  gemma3:1b  -> "thread_compile_order_q3"                                              0.857
  qwen0.5b   -> "COMPILE-ORDER-Q3, PRIMARY_OPEN_THREAD_ID: thread_compile_order_q3,

The 0.5B model scored HIGHER by dumping more tokens. It shotgunned every identifier it could see and hit all seven dimensions. The 1B model gave a precise, correct, concise answer and lost correct_next_action because it did not also recite the next action.

ROOT CAUSE: every continuity dimension is "does the answer contain token X". Pure RECALL, zero PRECISION. A maximally verbose answer that names everything wins. That is the M1 audit disease wearing a new costume -- the metric is maximised by a strategy that is not the intended behaviour. Fourth instance of this class today (goal-echo scoring 1.0; silence scoring 0.43; question-parroting scoring 0.571; now shotgunning scoring 1.0).

CONSEQUENCE: NEITHER M1 NOR M2 IS INTERPRETABLE ACROSS MODELS until this is fixed. The cross-model comparison is confounded with answer verbosity/style. Do not cite -0.054 as "the substrate nearly ties at 1B" -- that number is mostly a change in how gemma phrases answers.

WITHIN a single model the arms are still comparable (same model, same style, only structure differs), so the qwen 0.5B M2 = -0.205 stands as a within-model statement, bounded to identifier-retrieval tasks under this packet design.

FIX DIRECTION, not implemented -- this is a scoring design decision and I am not making it unilaterally after four self-inflicted scoring bugs today:
  (a) add a PRECISION term: penalise answers that name identifiers irrelevant to the asked dimension
  (b) enforce a concision budget so shotgunning is not free
  (c) score dimensions on the SPECIFIC span that answers the question rather than anywhere in the text
  (d) require the answer to be a single claim per dimension
I lean (b)+(c): cheapest, mechanical, and directly kills the dump strategy without needing semantics.

WHAT IS SOLID AND NOT AFFECTED:
- The harness mechanics. Two real subprocesses, distinct PIDs on all 48 rows in every run, model evicted between episodes, Episode B primed, corpus identity pinned, arms built from one frozen artifact set.
- broken_packet works as a floor and has repeatedly caught bugs by scoring impossibly high.
- The raw-text observation that a flat dump makes small models copy identifiers while a nested packet makes them paraphrase. That is in the generations, not the scoring.

FOR ANTHONY: this is the fourth scoring bug found today by refusing to accept a result that looked wrong. Each time the tell was a control behaving impossibly. The pattern is now the most reusable thing this project has produced: BEFORE trusting any metric, ask what the laziest strategy that maximises it looks like, and check whether a real system would ever do that.
