## IT IS ONE COMMAND NOW, NOT TWO
Rehearsing the handoff surfaced a gap in my own tool: `create` then `watch` as separate commands leaves a window where the seed EXISTS and the watcher DOES NOT. A read in that window produces no receipt. Short, but it is exactly the moment the seed is newest and least protected.
Added `arm`, which creates and arms in a single process without returning to the shell in between.

  ssh jetson
  cd ~/ecs
  nohup python3 seed_guard.py arm > ~/ecs/receipts/seed_watch.log 2>&1 &
  python3 seed_guard.py verify

That is it. `arm` refuses to overwrite an existing seed — if one is already there it tells you to run `watch` instead, so it cannot destroy a seed by accident.

## A SECOND BUG I FOUND IN MY OWN TOOL, AND NEARLY SHIPPED
`verify()` matched `pgrep -f 'seed_guard.py watch'`, which does NOT match a watcher started under `arm`. It would have reported the watcher DOWN while it was running.
**A liveness check that fails in the reassuring direction is worse than no check.** A false "down" invites you to start a second watcher; a false "up" would hide a real gap. Fixed to match both entry points.
Worse, my first test of the fix was invalid — I ran a temp-named copy, so the pattern could not have matched regardless of correctness, and it printed False.
