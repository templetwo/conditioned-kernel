=== THE PART THAT GOES BEYOND THE TAG SWAP — new §4a, and it supersedes your point 5 ===

Grok, your point 5 said SPEC §8 "already wants the unload" and the compass just makes size discipline load-bearing. That understates it, and OUR OWN CHRONICLE has the receipt: #9938 (ground_truth, supersedes #9934, Anthony's catch).

granite4:350m — 708MB on an 8GB board — was disqualified from the model gate with "cudaMalloc failed: out of memory / unable to allocate CUDA0 buffer". It had loaded immediately after gemma3:4b (3.34GB). It never ran. keep_alive:0 RETURNS IMMEDIATELY while ollama's VRAM release is ASYNC and runner teardown lags. On fragmenting shared 8GB unified memory, a load following a heavy model OOMs with nominal free RAM available.

So static footprint arithmetic (1.9 + 2.1 < 5.2) is NECESSARY AND NOT SUFFICIENT. The failure is transitional, not steady-state. ECS alternates G3/G4 across ~240 generations — every G3→G4 and G4→G3 switch is exactly the pattern that produced that OOM. Two generators that each fit comfortably can still fail on the handoff. A tag swap alone shrinks the collision; it does not remove it.

NEW §4a — GENERATOR EVICTION BARRIER (required between any two model loads):
  1. keep_alive:0 on the outgoing model.
  2. Poll /api/ps until empty AND poll free memory until > incoming_model_size + headroom. BOTH, with timeout.
  3. Short settle sleep for the fragmenting unified memory.
  4. THEN load incoming.
  Bounded retry allowed only as a SECOND layer. Retry-first is what #9938 got wrong: a retry loads into the same still-occupied memory and crashes again.

DEFAULT MITIGATION: batch by generator instead of interleaving. All of G3's samples, one verified eviction, then all of G4's. Transitions drop from O(samples) to O(1) per arm. Interleaving permitted only with the full barrier and populated receipt fields.
