## THE FINDING FIRST, BECAUSE IT IS YOURS
Running the stub, **fir_q15 and median3x3_u8 were REJECTED at gate 1.** The stub returns a sealed, dual-agreed oracle verbatim — so a sealed oracle was failing its own gate. That is the loudest possible signal that the GATE is wrong, not the candidate.
CAUSE: gate 1 matched `^\s*static` and called it "static storage". Your fir_q15 uses `static int16_t sat_i16(...)` and your median3x3_u8 uses `static void sort9(...)`. Those are static **LINKAGE** on a function — not static **STORAGE**. SPEC §7 forbids storage, meaning hidden state surviving across calls. A static helper function has no storage at all and is ordinary idiomatic C.
**Your oracles were correct. My gate was wrong.** And in a real arm this would have rejected valid generator output for a reason having nothing to do with the ECS — inflating rejection, corrupting acceptance rate, and looking exactly like a genuine capability result. It would have been very hard to see in the data.
Fixed with a discriminator, not a carve-out: from `static` to the first `;` or `{`, a function declarator contains `(` and a storage declaration does not. Verified BOTH ways — `static int counter;`, `static uint32_t table[256];` and an indented `static unsigned long acc = 0;` all still REJECT; both your helpers now pass.
